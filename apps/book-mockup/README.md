# book-mockup — 책 만들기 서비스 목업

`docs/specs/2026-10-11-book-service-design.md`(책 만들기 서비스 기획)의 클릭되는 HTML 목업이다.
빌드와 의존성이 없는 파일 하나(`index.html`)라 npm workspace에 넣지 않았고, kayak도 쓰지 않는다.

## 여는 법

`index.html`을 브라우저로 연다. 서체(나눔명조, 나눔고딕, IBM Plex Sans KR)는 Google Fonts에서 받으므로
오프라인이면 시스템 서체로 보이고 쪽 나눔도 달라진다.

## 들어 있는 것

- 내 책 → ① 원고 넣기 → ② 차례 확인 → ③ 책 꾸미기 → ④ 미리보기 → ⑤ 점검·내보내기, 그리고 책 작업실
- 위의 "기획 요약" 탭: 기획서 요약
- 위의 "기회 나무" 탭: Opportunity Solution Tree(바라는 결과 → 기회 → 해결책 → 가정 시험)와 먼저 시험할 가정 5가지.
  데이터는 스크립트의 `OST`, `OST_FIRST`. 기회는 인터뷰 전 가설이다
- 책 표기(`docs/specs/2026-10-12-book-markup-design.md`): 붙여넣기·워드·작업실의 "표기로 보기"가 같은 읽기(`parseManuscript`)를 쓴다.
  가져오기 방식(자동 인식 사용)과 표기 방식(자동 인식 없음), 정규 표기 쓰기(`serializeSection`)
- 모양 사전: 3단계 "이 책의 모양들"에서 상자별 모양, 강조·한자 병기 방식, 모르는 이름 대응을 고치면 미리보기가 바로 바뀐다
- 작업실 편집기: 상자는 이름표가 붙은 틀, 강조는 방점, 한자는 읽기가 붙어 보인다. 도구 막대로 상자·강조·굵게·한자 병기·주석·그림·장면 바꿈·새 쪽을 넣는다
- 예시 원고("바다로 가는 길")에는 점검 화면을 보여 주려고 이모티콘(서체에 없는 글자), 해상도가 낮은 사진, 긴 주석,
  사전에 없는 상자 이름(`::: 일기`)을 일부러 넣었다

## 한계

- 미리보기의 쪽 나눔은 브라우저 글꼴과 DOM 측정으로 흉내 낸 것이다. 규칙(장 오른쪽 시작, 빈 면, 외톨이 줄 피하기,
  쪽 아래 주석 자리, 그림 미루기, 4의 배수 쪽)은 기획서 10.2와 같지만 줄바꿈은 kayak과 다를 수 있다.
- 워드 파일 올리기는 실제 파일을 읽지 않고 예시 원고를 대신 읽는다. PDF 내보내기도 진행 표시만 한다.
- 상태는 메모리에만 있어 새로고침하면 처음으로 돌아간다.
- 책 표기 규격 중 목업에 없는 것: 줄 끝 `\` 줄바꿈, 워드 스타일 이름 대응과 "처음 보는 스타일" 질문, 비슷한 이름을 글자 비교로 고르기(별칭 표만 씀).
- 방점·루비는 브라우저 CSS(`text-emphasis`, `<ruby>`)로 흉내 낸다. kayak에는 아직 없다(기획서 K8, K9).

## 고칠 때

- 파일 하나에 CSS·HTML·JS가 모두 있다. 표기 읽기는 `parseManuscript()`, 글자 표기는 `tokenize()`, 표기 쓰기는 `serializeSection()`,
  모양 사전은 `resolveBox()`·`PRESET_BOXES`, 조판 흉내는 `paginate()`, 점검은 `runChecks()`.
- 사내 공유 페이지(Artifact)로도 올라가 있다: https://claude.ai/artifact/KeATca2GmLVqQmDKK5Ux3B .
  공유 페이지용은 문서 머리(`<!doctype>`, `<head>`)가 게시할 때 붙으므로 이 파일에서 그 부분만 빼고 올린다.
