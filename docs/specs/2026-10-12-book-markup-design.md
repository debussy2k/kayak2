# 책 표기와 모양 사전 — 원고의 의미와 책의 모양을 잇는 층

- 날짜: 2026-10-12
- 상태: 방향 승인됨(의미 표기 + 모양 사전, Markdown과 겹치는 문법). 규격 초안, 검토 대기
- 상위 기획: `docs/specs/2026-10-11-book-service-design.md` (이 문서가 그 6.1 원고 넣기, 6.6 책 디자인, 10.1 Book JSON을 넓힌다)
- 목업: `apps/book-mockup/index.html`

## 1. 목적

작가가 원고에 **"이것이 무엇인가"**만 쉽게 적고, **"어떻게 보이는가"**는 책 디자인이 정하게 한다.
이를 위해 두 가지를 정한다.

- **책 표기:** 원고에 의미를 붙이는 가벼운 글자 규칙. 사람이 읽고 쓸 수 있는 Book JSON의 글 형태다.
- **모양 사전:** 의미 이름(시, 편지, 강조 …)을 책의 모양(들여쓰기, 서체, 상자 …)으로 바꾸는 표. 디자인 프리셋마다 하나씩 있다.

조사 근거(Scrivener 섹션 유형/레이아웃, Vellum 텍스트 기능/스타일, Pandoc `custom-style`, Typst set/show 규칙, Markua, VFM, でんでんマークダウン)는 이 문서를 만든 대화의 조사 결과에 있다. 요점: 모양은 이름 대응으로 정하고, 표기는 기존 Markdown과 어긋나지 않게 하며, 동아시아 책에 필요한 요소(한자 병기, 방점)를 더한다.

## 2. 원칙

1. **모양이 아니라 의미를 쓴다.** 원고에는 `::: 시`만 있고 "왼쪽 2자 들여쓰기"는 모양 사전에 있다.
2. **표기를 몰라도 책이 된다.** 대부분의 작가는 도구 버튼, 워드 가져오기, 자동 인식만 쓴다. 표기는 그 결과를 담는 형식이고, 직접 치는 것은 선택이다.
3. **기호를 지워도 읽힌다.** 렌더링하지 않은 원고가 그대로 읽혀야 한다.
4. **Markdown·Pandoc과 겹치는 곳은 같게.** `#`, `>`, `**`, `*`, `***`, `:::`, `[^1]`, `![]()`는 같은 뜻이다. 다른 점은 5절에 모두 적는다.
5. **한국 작가의 입력 습관에 맞춘다.** 줄바꿈 하나가 새 문단이고, 표기 자리의 전각 기호도 받아 준다.

## 3. 범위

**이 문서:** 표기 문법, 두 가지 읽기 방식, 모양 사전의 구조와 기본값, 오류 처리, Book JSON 대응과 왕복 규칙, 편집기 표시, 워드 가져오기 대응.

**하지 않는 것:** 책 정보(제목, 지은이, 판권)는 표기에 넣지 않는다 — 1단계 화면에서 받는다. 표, 수식, 다단, 색인은 이번 범위 밖이다.

## 4. 표기 — 네 단계

### 4.1 0단계: 자동 인식 (가져오기 때만)

표기가 없는 줄에만 적용한다. 규칙은 상위 기획 6.1과 같다.

| 원고 | 해석 | 확실성 |
|---|---|---|
| `제1장 바다로 가는 길`, `1장 …`, `Chapter 1 …` (40자 이하 한 줄) | 장. 번호는 버리고 저절로 매긴다 | 확실 |
| `제1부 …`, `1부 …` | 부 표지 | 확실 |
| `여는 글`, `프롤로그`, `들어가며`, `머리말`, `작가의 말` | 여는 글 | 확실 |
| `닫는 글`, `에필로그`, `나가며`, `맺음말` / `감사의 글` / `작가 소개`, `지은이 소개` | 각 부분 | 확실 |
| 빈 줄 사이의 30자 이하 한 줄, 문장부호로 끝나지 않음 | 소제목 (장 후보로 표시) | 약함 — 2단계(차례 확인)에서 묻는다 |
| `* * *`, `***`, `---`, `+++`, `# # #` | 장면 바꿈 | 확실 |

### 4.2 1단계: 기본 표기 8가지

설명 한 장으로 익힐 수 있는 범위다. 모든 표기 기호는 **줄 맨 앞**(앞 공백 허용) 또는 **글 속 괄호**에서만 뜻을 갖는다.

| 표기 | 뜻 | 예 |
|---|---|---|
| `# 제목` | 새 부분(기본은 장). 제목이 `여는 글` 등 4.1의 이름이면 그 부분 | `# 바다로 가는 길` |
| `## 소제목`, `### 작은 제목` | 장 안의 제목 | `## 어느 일요일` |
| `***` (별 3개 이상, 사이 공백 허용) | 장면 바꿈 | `* * *` |
| `[주: 내용]` | 주석. 위치(쪽 아래/장 끝/책 끝)는 디자인이 정함 | `멸치젓[주: 봄에 잡은 멸치를 …]` |
| `[그림: 파일 \| 설명 \| 크기]` (한 줄 전체) | 그림. 설명·크기는 생략 가능. 크기: `본문 폭`(기본), `반 폭`, `한 면` | `[그림: 부엌.jpg \| 할머니의 부엌 \| 반 폭]` |
| `> 글` | 인용 (`::: 인용`의 줄임) | `> 사람은 바다를 닮는다.` |
| `**글**` | 굵게 | |
| `*글*` | 강조 (모양은 디자인이 정함: 방점, 다른 서체, 굵게, 밑줄) | `그날은 *정말* 추웠다` |

추가 규칙:

- **부분 종류 지정:** 제목 줄 끝에 `{종류}`를 붙인다. `# 바다에게 {여는 글}`. 종류: `여는 글`, `헌사`, `부`, `장`, `닫는 글`, `감사의 글`, `작가 소개`.
- **Pandoc식 주석도 받는다:** 본문 `…했다[^편지].`, 같은 부분 안의 줄 `[^편지]: 내용`. 저장할 때는 `[주: …]`로 바꾼다.
- **Markdown식 그림도 받는다:** `![설명](파일)`은 `[그림: 파일 | 설명]`과 같다.
- **문단 안 줄바꿈:** 줄 끝 `\`는 문단을 나누지 않고 줄만 바꾼다(CommonMark의 강제 줄바꿈과 같음).

### 4.3 2단계: 이름 붙은 상자와 글자

**블록 상자**

```
::: 시
바다는 파랗고
할머니는 웃었다

다음 여름에도
:::
```

- 여는 줄 `::: 이름`, 닫는 줄 `:::`. 콜론은 3개 이상이면 된다.
- 상자 안의 줄은 상자의 **줄 처리**(6.2)에 따른다. `문단`이면 줄마다 문단, `행`이면 줄마다 행이고 빈 줄은 연 나눔이다.
- 상자 안에 상자는 넣지 않는다(7절 B2).
- 기본 이름: `인용`, `시`, `편지`, `문자`, `상자`, `가운데`, `작게`. 별칭: `운문`·`노래`·`가사` → 시, `쪽지` → 편지, `메시지`·`카톡` → 문자, `참고`·`팁`·`알림` → 상자.

**글자 꾸밈**

| 표기 | 뜻 |
|---|---|
| `[글]{이름}` | 글에 이름 붙이기. 기본 이름: `방점`, `위`(위첨자), `아래`(아래첨자), `원어` |
| `[글]{이름: 값}` | 값이 있는 이름. `[學而時習之]{한자: 학이시습지}` |
| `{漢字\|한자}` | `[漢字]{한자: 한자}`의 줄임 (VFM·でんでん의 루비 표기와 같은 모양) |

`한자`의 모양은 디자인이 정한다: 괄호 병기 `學而時習之(학이시습지)`(기본), 위에 작게(루비), 한자만.

### 4.4 3단계: 배치 지시 (드물게)

디자인 규칙을 한 곳에서만 어길 때 쓴다. 한 줄 전체여야 한다.

| 표기 | 뜻 | 받아 주는 변형 |
|---|---|---|
| `[새 쪽]` | 여기서 다음 쪽으로 | `[새쪽]`, `[쪽 넘김]`, `[다음 쪽]` |
| `[새 오른쪽 면]` | 다음 오른쪽 면으로 (필요하면 빈 면) | `[오른쪽 면에서]` |

### 4.5 글자 그대로 쓰기

표기 기호를 글자로 쓰려면 앞에 `\`를 붙인다: `\*`, `\[`, `\]`, `\{`, `\}`, `\|`, `\#`, `\>`, `\:`, `\\`.
줄 맨 앞이 아니거나 짝이 맞지 않는 기호는 표시 없이 글자로 남는다(예: 문장 속 `*` 하나).

## 5. Markdown과 다른 점

| | Markdown(CommonMark) | 책 표기 | 이유 |
|---|---|---|---|
| 줄바꿈 하나 | 무시(앞 줄에 이어짐) | **새 문단** | 한글·워드에서 붙여넣은 원고와 시가 한 문단으로 뭉치지 않게 |
| 빈 줄 | 문단 나눔 | 상자 밖에서는 의미 없음, `행` 상자 안에서는 연 나눔 | 작가마다 빈 줄 습관이 달라서 |
| `_글_` | 강조 | 글자 그대로 | 한국어 원고에서 쓸 일이 적고, 오인식을 줄이려고 |
| 들여쓴 코드 블록, 목록, 표, HTML | 있음 | 없음 (글자 그대로) | 책 원고에 거의 없고, 들여쓰기 습관과 부딪힘. 목록은 나중에 |
| 전각 기호 | 글자 | 표기 자리의 `＃ ＞ ＊ ［ ］ ｛ ｝ ｜ ：`는 반각과 같은 기호로 봄. 표기가 되지 않으면 원래 글자를 둔다 | 한글 입력 중에 전각이 섞여 들어와서 |
| `[주: …]`, `[그림: …]`, `{漢\|한}`, `[새 쪽]` | 없음 | 있음 | 한국어로 읽히는 표기. Pandoc의 `^[…]`, `![]()`에 대응 |

## 6. 모양 사전

### 6.1 구조

책 하나가 쓰는 모양 사전 = **디자인 프리셋의 기본 사전** + **이 책에서 고친 것** + **이 책의 이름 대응**(모르는 이름 → 아는 모양).
프리셋을 바꾸면 기본 사전이 바뀌고, 작가가 고친 항목은 남는다.

### 6.2 상자 모양의 속성

작가에게는 쉬운 말과 선택지로만 보인다.

| 속성 | 선택지 | 코드에서의 대응 (kayak 문단 속성 등) |
|---|---|---|
| 줄 처리 | 문단 / 행 | 조판기: `행`이면 줄마다 첫 줄 들여쓰기 없이, 빈 줄은 연 간격 |
| 왼쪽·오른쪽 들여쓰기 | 없음, 1자, 2자, 3자 | `lindent`, `rindent` (px = 자 × 본문 글자 크기) |
| 정렬 | 본문과 같게, 왼쪽, 가운데, 오른쪽 | `set_text_align` |
| 마지막 줄 | 그대로, 오른쪽 (편지 서명) | 마지막 문단에만 정렬 오른쪽 |
| 글자 크기 | 작게(−1pt), 조금 작게(−0.5pt), 같게 | 글자 크기 |
| 서체 | 본문 서체, 다른 서체(명조 ↔ 고딕) | 서체 패밀리 |
| 위아래 간격 | 없음, 반 줄, 한 줄 | `space_before`, `space_after` |
| 꾸밈 | 없음, 위아래 선, 왼쪽 선, 상자, 말풍선 | 조판기가 그리는 도형(SVG). kayak 글자 렌더와 별개 |
| 쪽 나눔 | 나눠도 됨, N줄 이하면 한 쪽에 | 조판기 규칙 |

### 6.3 글자 모양의 속성

| 이름 | 선택지 | 기본 |
|---|---|---|
| 강조 (`*글*`) | 방점, 다른 서체, 굵게, 밑줄 | 에세이·소설: 방점 / 실용: 굵게 |
| 굵게 (`**글**`) | 굵게 | 서체의 Bold 스타일 (kayak의 `bold` 속성은 SVG에 효과가 없으므로 상위 기획 K5) |
| 한자 | 괄호 병기, 위에 작게, 한자만 | 괄호 병기 |
| 방점, 위, 아래, 원어 | 고정 | — |

### 6.4 프리셋별 기본값

| 이름 | 에세이 | 소설 | 실용 |
|---|---|---|---|
| 인용 | 왼쪽 2자, 조금 작게 | 왼쪽 2자, 조금 작게 | 왼쪽 선, 조금 작게 |
| 시 | 행, 왼쪽 2자, 8줄 이하 한 쪽 | 행, 왼쪽 3자, 8줄 이하 한 쪽 | 행, 왼쪽 2자 |
| 편지 | 왼쪽·오른쪽 2자, 조금 작게, 마지막 줄 오른쪽 | 같음 | 상자, 마지막 줄 오른쪽 |
| 문자 | 다른 서체, 말풍선, 작게 | 다른 서체, 위아래 선, 작게 | 다른 서체, 말풍선, 작게 |
| 상자 | 위아래 선 | 위아래 선 | 상자, 위아래 반 줄 |
| 가운데 | 가운데 | 가운데 | 가운데 |
| 작게 | 작게 | 작게 | 작게 |

### 6.5 모르는 이름

`::: 일기`처럼 사전에 없는 이름은 **기본 상자**(꾸밈 없음, 본문과 같음)로 조판하고 점검에서 묻는다:
"‘일기’ 모양이 아직 없어요. 비슷한 ‘편지’ 모양을 쓸까요, 새 모양을 만들까요?"
답은 이 책의 이름 대응에 저장한다. 비슷한 이름은 별칭 표와 글자 비교로 고른다.

## 7. 오류와 점검

표기 오류로 원고를 거부하지 않는다. 가장 그럴듯하게 읽고, 점검의 "확인해 보세요"에 줄 번호와 함께 남긴다.

| 코드 | 상황 | 읽는 방법 | 작가에게 보이는 말 |
|---|---|---|---|
| B1 | `::: 이름`이 닫히지 않음 | 다음 `#` 제목 또는 원고 끝에서 닫음 | "12줄에서 시작한 ‘시’ 상자가 끝나지 않았어요. 어디까지인지 확인해 주세요" |
| B2 | 상자 안에서 또 `::: 이름` | 앞 상자를 닫고 새 상자를 시작 | "상자 안에 상자를 넣을 수 없어서 따로 나눴어요" |
| B3 | 여는 줄 없이 `:::`만 | 무시 | 알리지 않음 |
| N1 | 모르는 상자·글자 이름 | 기본 상자 / 글자 그대로 | 6.5 |
| I1 | 닫히지 않은 `[주:`, `[그림:` | 글자 그대로 | "‘[주:’로 시작한 주석이 ‘]’로 끝나지 않았어요" |
| I2 | 정의 없는 `[^이름]` / 쓰이지 않은 `[^이름]:` | 글자 그대로 / 버리지 않고 표시 | "‘편지’ 주석의 내용이 없어요" |
| G1 | 그림 파일이 없음 | 빈 그림 자리 | 고쳐야 해요: "‘부엌.jpg’ 파일을 올려 주세요" |
| G2 | 모르는 크기 말 | 본문 폭 | "‘크게’는 모르는 크기예요. 본문 폭으로 넣었어요" |

## 8. Book JSON 대응과 왕복

### 8.1 대응

| 표기 | Book JSON (상위 기획 10.1을 넓힘) |
|---|---|
| `# 제목 {종류}` | 새 `section { kind, title }` |
| `##`, `###` | `{ type: "heading", level: 2 \| 3, runs }` |
| 문단 | `{ type: "paragraph", runs }` |
| `::: 이름` | `{ type: "box", name, blocks }`. `>` 인용은 `name: "인용"` |
| 상자 안 빈 줄 | `{ type: "gap" }` (상자 안에서만 저장) |
| `***` | `{ type: "break" }` |
| `[그림: …]` | `{ type: "image", src, caption, size: "body" \| "half" \| "page" }` |
| `[새 쪽]`, `[새 오른쪽 면]` | `{ type: "directive", kind: "newPage" \| "newRecto" }` |
| `**글**`, `*글*` | run의 `marks: ["strong"]`, `["emph"]` |
| `[글]{이름: 값}`, `{漢\|한}` | run의 `span: { name, value }` |
| `[주: …]` | run `{ noteRef: id }` + 부분의 `notes[id]` |

### 8.2 두 가지 읽기 방식

- **가져오기 방식:** 붙여넣기, .docx, 텍스트 파일. 0단계 자동 인식을 쓰고, 별칭·Pandoc식·Markdown식을 받는다.
- **표기 방식:** 편집기의 "표기로 보기"에서 고친 글. 자동 인식을 **쓰지 않는다**. 작가가 "본문으로 두기"를 고른 짧은 줄이 다시 장 후보가 되지 않게 하려는 것이다.

### 8.3 정규 표기와 왕복 규칙

Book JSON을 글로 쓸 때는 한 가지 정규 형태만 쓴다: `#`/`##`/`###`, `***`, `[주: …]`, `[그림: 파일 | 설명 | 크기]`, `::: 이름`(단, 인용은 `> `), `**`, `*`, `{漢|한}`(한자), `[글]{이름}`, `[새 쪽]`. 장 번호는 쓰지 않는다.

테스트로 고정할 성질:

- **P1** 모든 Book JSON `J`에 대해 `읽기_표기(쓰기(J)) = J`.
- **P2** 모든 글 `T`에 대해 `쓰기(읽기(T))`는 한 번 더 돌려도 같다(정규화가 멱등).
- **P3** 표기가 없는 원고는 가져오기 뒤 정규 표기로 써도 문장이 바뀌지 않는다(제목 번호 제거와 공백 정리만).

## 9. 편집기 표시

편집기는 기호 대신 의미를 보여 준다(보이는 대로 편집하되 의미가 드러나는 방식). 표기는 저장 형식이다.

| 표기 | 편집기에서 |
|---|---|
| `::: 시` | 왼쪽에 "시" 이름표가 붙은 상자. 이름표를 누르면 이름 바꾸기 / 상자 풀기 |
| `*강조*`, `**굵게**` | 밑에 점선, 마우스를 올리면 "강조" |
| `{漢\|한}` | 한자 위에 작은 읽기 |
| `[주: …]` | 번호 칩. 오른쪽 주석 칸에 내용 |
| `[새 쪽]` | 점선 가로줄과 "새 쪽" |

- 도구 막대: 소제목, 상자(이름 고르기), 강조, 굵게, 한자 병기, 주석, 그림, 장면 바꿈.
- **표기로 보기:** 장 하나를 정규 표기 글로 보여 주고 고칠 수 있게 한다. 돌아올 때 표기 방식으로 읽고, 오류는 줄에 표시한다. 중급 이상 작가와 대량 수정용이다.

## 10. 워드 가져오기 대응

| 워드 | 표기 |
|---|---|
| 제목 1 / 제목 2 / 제목 3 | `#` / `##` / `###` |
| 인용, 강한 인용 | `>` |
| 스타일 이름이 시·Poem·Verse·운문 | `::: 시` (6.4 별칭 표 전체 적용) |
| 각주, 미주 | `[주: …]` |
| 굵게 / 기울임 | `**` / `*` |
| 가운데 정렬 문단이 연속 | `::: 가운데` |
| 처음 보는 문단 스타일이 3번 이상 쓰임 | 가져오기 끝에 한 번 묻는다: "‘메모체’ 스타일은 무엇인가요? 본문 / 인용 / 시 / 편지 / 상자 / 새 모양" — 답을 작가 계정에 기억 |

## 11. 구현 메모

- 문법은 Markdown·Pandoc과 겹치게 정했지만 5절의 차이(특히 줄바꿈 = 문단) 때문에 CommonMark 파서를 그대로 쓰기 어렵다. 선택지는 둘이다. 계획 단계에서 정한다.
  - remark(mdast)로 읽은 뒤 문단을 줄 단위로 나누는 변환과 micromark 확장(주, 그림, 한자, 지시)을 더하는 방식. VFM이 걸은 길이다.
  - 줄 단위 블록 읽기 + 작은 글자 읽기를 직접 만드는 방식. 표기가 15가지 남짓이고, 7절처럼 줄 번호가 있는 한국어 오류 메시지가 필요하다.
  - 제안: 직접 만든다. 대신 Markdown·Pandoc 내보내기(쓰기)는 따로 만든다.
- 모양 사전은 서비스 층에서 풀어 kayak에는 구체 속성만 넘긴다. kayak에 "이름 붙은 문단 스타일"을 두지 않는다.
- 엔진에 필요한 것(상위 기획 10.4에 추가): **K8 방점**(글자 위 점. 위첨자 K4와 같은 글자 장식 계열), **K9 루비**(한자 "위에 작게". 첫 출시는 괄호 병기만 하므로 나중).

## 12. 열린 질문

1. 내보내기 형식: 책 표기 원문(.txt)과 Markdown/Pandoc(.md) 변환본을 첫 출시에 둘 다 줄지.
2. 작가가 만든 새 모양을 다른 책에서도 쓰게 할지(계정 단위 사전).
3. 목록(1. 2. 3., 글머리표)을 실용서 때문에 첫 출시에 넣을지.
4. `*강조*`의 기본 모양을 에세이·소설에서 방점으로 할지, 다른 서체로 할지 — 사용성 시험에서 정한다.
