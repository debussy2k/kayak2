# 책 만들기 서비스 기획 — "원고를 책으로"

- 날짜: 2026-10-11
- 상태: 방향 승인됨(진행 방식 A, 장은 오른쪽 면 시작, 주석 위치는 책 전체에 하나). 기획서 검토 대기
- 목업: 클릭되는 HTML 프로토타입 `apps/book-mockup/index.html`(사내 공유 페이지 https://claude.ai/artifact/KeATca2GmLVqQmDKK5Ux3B) — 화면 구성은 8절. 미리보기는 브라우저 글꼴로 흉내 낸 조판이며 10.2의 규칙을 그대로 따른다
- 범위 밖: 책표지, 전자책(EPUB), 인쇄 주문·결제
- 이어지는 설계: `docs/specs/2026-10-12-book-markup-design.md` (책 표기와 모양 사전 — 6.1, 6.6, 10.1을 넓힌다),
  `docs/specs/2026-10-12-book-images-design.md` (책 속 사진 — 6.4를 대신하고 3, 6.6, 10.1, 10.4를 넓힌다)

## 1. 목적

글을 다 쓴 일반 작가가 원고만 넣으면 인쇄소에 넘길 수 있는 책 내지 PDF를 얻게 한다.
서비스가 차례를 만들고 장을 나누고, 장 시작 면(도비라)·여는 글/닫는 글·쪽 번호·머리글·홀수/짝수 면 규칙·사진·주석을 알아서 배치한다.
작가는 조판 용어를 몰라도 되고, 필요한 만큼만 고친다.

이 서비스는 kayak의 첫 번째 "여러 쪽" 사용처다. 지금 kayak은 텍스트 상자 하나를 전제하므로, 이 서비스가 로드맵의 공개 API 재설계(#1)와 영역/흐름(#2)의 구체적인 요구사항이 된다(10절).

## 2. 사용자와 성공 기준

| 사용자 | 예 | 바라는 것 |
|---|---|---|
| 첫 책 작가 (주) | 자서전, 에세이, 여행기, 가족 문집 | 손대지 않아도 "책처럼" 보이는 결과, 모르는 말이 없는 화면, 실수해도 되돌릴 수 있음 |
| 독립출판 작가 | 소설, 시집, 소책자 | 서체·글자 크기·여백 정도의 조정, 장 시작 모양 선택, 각주 |
| 실용서 작가 | 강의록, 안내서 | 소제목 체계, 사진과 설명, 주석 |

**성공 기준**

- 첫 책 작가가 도움말 없이 원고 넣기 → PDF 받기까지 마친다(목표 20분 이내, 원고 200쪽 기준).
- 화면에 나오는 말은 모두 9절 용어표의 "작가에게 보이는 말"이다. 조판 용어는 툴팁으로만.
- 미리보기와 인쇄 PDF의 줄바꿈·쪽 나눔이 같다(같은 엔진, 같은 폰트, 같은 계산).
- 인쇄소 입고 기준을 만족한다: 판형 + 재단 여백 3mm, 폰트 아웃라인, 총 쪽수 4의 배수, 사진 300dpi 경고.

## 3. 범위

**첫 출시(MVP)**

- 원고 넣기: 붙여넣기, 워드(.docx) 올리기, 서비스 안에서 직접 쓰기(단순 편집기)
- 장 자동 인식과 차례 확인·수정
- 책 구조: 앞부분(속표지, 판권 면, 헌사, 차례, 여는 글) / 본문(부·장·소제목) / 뒷부분(닫는 글, 감사의 글, 책 끝 주석, 작가 소개)
- 홀수/짝수 면 규칙, 장 시작 면, 쪽 번호, 머리글
- 사진(사진함, 자동 배치, 크기·자리 지정, 사진 묶음, 한 면·펼침면 — 사진 밀도 A·B), 주석(쪽 아래 / 장 끝 / 책 끝 중 하나)
- 책 디자인 프리셋 4개(에세이, 소설, 실용, 여행)와 쉬운 조정 4가지
- 펼침면 미리보기, 인쇄 전 점검, 인쇄용 PDF와 확인용 PDF 내보내기

**나중에**

- 프리셋 추가(사진책 — 사진 밀도 C, 시집), 세밀한 스타일 편집(문단 스타일별 서체·간격)
- 한글(.hwpx) 올리기, 다단, 표, 색인, 참고문헌 자동 정리
- EPUB, 표지 서비스와 연결(쪽수 → 책등 두께 전달)

## 4. 사용자 흐름 (A안: 단계 안내 → 책 작업실)

처음 만들 때는 다섯 단계를 순서대로 안내한다. 각 단계는 기본값이 채워져 있어 "다음"만 눌러도 끝까지 간다.
한 번 끝까지 간 책은 이후 "책 작업실"에서 연다. 작업실은 왼쪽 차례, 가운데 원고, 오른쪽 펼침면 미리보기다.

```
[내 책] → ① 원고 넣기 → ② 차례 확인 → ③ 책 꾸미기 → ④ 미리보기 → ⑤ 점검·내보내기
                                         ↑                         │
                                         └──── 책 작업실 ←─────────┘
```

| 단계 | 작가가 하는 일 | 서비스가 하는 일 |
|---|---|---|
| ① 원고 넣기 | 책 제목·지은이, 책 크기 선택. 원고를 붙여넣거나 .docx를 올리거나 "직접 쓰기" | 원고를 블록(제목·문단·인용·사진·주석)으로 바꾼다 |
| ② 차례 확인 | 찾은 장 목록을 보고 순서·이름·종류를 고친다. 장을 나누거나 합친다 | 장 후보와 그 근거(제목 스타일, "제1장" 패턴 등)를 보여 준다 |
| ③ 책 꾸미기 | 프리셋 고르기, 글자 크기·줄 간격·본문 서체, 사진 크기, 장 시작 모양, 쪽 번호·머리글, 주석 위치 | 바뀔 때마다 오른쪽 견본 펼침면을 다시 그린다 |
| ④ 미리보기 | 펼침면을 넘겨 본다. 고칠 곳을 누르면 그 자리 원고로 간다. 사진은 눌러서(사진 카드) 또는 끌어서 고친다 | 전체 조판, 쪽 번호, 빈 면 표시, 사진을 놓은 이유 |
| ⑤ 점검·내보내기 | 점검 결과를 보고 "그대로 두기" 또는 "고치러 가기" | 7절의 점검, PDF 생성 |

## 5. 책 구조

책은 세 구역과 그 안의 "부분(section)"으로 이뤄진다. 부분마다 종류가 있고, 종류가 시작 면·쪽 번호·머리글 규칙을 정한다.

| 구역 | 부분 종류 | 기본 규칙 |
|---|---|---|
| 앞부분 | 속표지, 판권 면, 헌사, 차례, 여는 글 | 쪽 번호 숨김(선택: 로마 숫자). 속표지·헌사·차례·여는 글은 오른쪽 면 시작, 판권 면은 속표지 뒷면(왼쪽) |
| 본문 | 부 표지, 장 | 장은 오른쪽 면 시작, 첫 면은 장 시작 면. 본문 첫 쪽이 1쪽 |
| 뒷부분 | 닫는 글, 감사의 글, 책 끝 주석, 작가 소개 | 오른쪽 면 시작. 쪽 번호는 본문에서 이어짐 |

- 속표지·판권 면·차례는 서비스가 만든다. 판권 면은 ① 단계 정보(제목, 지은이, 펴낸 날)와 선택 입력(펴낸 곳, ISBN)으로 채운다.
- 차례는 조판이 끝난 뒤 장 제목과 시작 쪽으로 채운다. 앞부분 쪽 번호를 본문과 따로 매기므로 차례 길이가 바뀌어도 본문 쪽 번호는 그대로다.
- 장 안의 제목은 두 단계(소제목, 작은 제목)까지만 둔다.

## 6. 기능 상세

### 6.1 원고 넣기와 장 자동 인식

원고는 모두 **책 표기**로 읽는다(`2026-10-12-book-markup-design.md`). 아래 자동 인식은 그 문서의 0단계이고, 작가가 직접 쓰는 표기(`#`, `::: 시`, `[주: …]` 등)가 있으면 그것이 먼저다.

- **.docx:** 제목 1/2/3 스타일 → 장/소제목/작은 제목. 각주·미주, 사진(그림), 굵게·기울임, 인용(들여쓴 문단 스타일)을 가져온다. 그 밖의 서식(글꼴, 색, 크기)은 버린다 — 책 디자인이 정한다.
- **붙여넣기·직접 쓰기:** 책 표기 규격 4.1의 자동 인식 표를 따른다 — 장 번호 줄(`제1장`, `1장`, `Chapter 1`), 부(`제1부`), 여는 글·닫는 글·감사의 글·작가 소개 같은 이름, 빈 줄 사이의 짧은 한 줄(약한 장 후보, 점선 표시). 근거를 함께 저장해 ② 단계에서 보여 준다.
- 장 후보가 하나도 없으면 원고 전체를 장 하나로 두고 ② 단계에서 "장을 나눌 곳을 눌러 주세요"로 안내한다.
- 붙여넣은 HTML은 문단·굵게·기울임·줄바꿈만 남긴다(kayak의 붙여넣기 정리와 같은 방향).
- 화면의 도움말은 책 표기 1단계 8가지(장 `#`, 소제목 `##`, 장면 바꿈 `***`, 주석 `[주: …]`, 그림 `[그림: …]`, 인용 `>`, 굵게 `**`, 강조 `*`)를 한 장으로 안내한다.

### 6.2 홀수/짝수 면 규칙

| 규칙 | 기본값 | 작가에게 보이는 옵션 |
|---|---|---|
| 장 시작 위치 | 오른쪽 면 | "장은 오른쪽 면에서 시작" 켜기/끄기 (끄면 다음 면) |
| 빈 면 | 장 시작을 맞추려고 넣은 면은 쪽 번호·머리글 숨김 | 없음 |
| 쪽 번호 | 바깥쪽 아래 | 바깥쪽 아래 / 가운데 아래 / 바깥쪽 위 |
| 머리글 | 왼쪽 면: 책 제목, 오른쪽 면: 장 제목 | 켜기/끄기 |
| 장 시작 면 | 머리글·쪽 번호 숨김 | 없음 |
| 안쪽 여백 | 바깥쪽보다 넓게. 300쪽 넘으면 100쪽마다 1mm 더함 | 없음 (무선 제본 기준) |
| 총 쪽수 | 4의 배수가 아니면 뒤에 빈 면을 더하겠다고 점검에서 알림 | 점검에서 확인 |

### 6.3 장 시작 면

장 시작 면 스타일은 프리셋마다 둘 중 하나다.

- **같은 면 시작:** 장 시작 면 위쪽 1/3을 비우고 장 번호·장 제목을 놓은 뒤 바로 본문을 이어 쓴다.
- **한 면 전체 (도비라):** 장 번호·제목만 있는 면을 오른쪽에 두고, 본문은 그다음 오른쪽 면(또는 바로 뒤 왼쪽 면 — 프리셋이 정함)에서 시작한다.

부 표지는 항상 한 면 전체이고 뒷면은 비운다.

### 6.4 사진

전체 규격은 `2026-10-12-book-images-design.md`. 요점:

- **사진함:** 책마다 하나. 편집기·사진함·워드로 들어온 사진이 모두 모이고, 원고는 사진함 항목을 가리킨다. 쓰인 곳 / 아직 안 씀 표시, 사진 바꾸기.
- **자동 배치:** 크기·자리를 비워 두면 조판기가 사진 비율과 해상도로 본문 폭 / 반 폭을 고르고 앵커(앞 문단) 자리에 놓는다. 자리가 없으면 85%까지 줄이거나 다음 쪽 맨 위로 미룬다(원고 순서와 한 쪽 이내). 연달아 넣은 사진은 높이 맞춘 줄로 묶는다.
- **의도 지정:** 배치는 쪽 좌표가 아니라 말(크기: 본문 폭 / 반 폭 / 한 면 / 펼침면, 자리: 그 자리 / 쪽 위 / 쪽 아래 / 글 옆)로 저장한다. 책 꾸미기의 "사진 크기", 사진 카드, 미리보기에서 끌기 셋 다 이 말을 쓴다.
- 해상도: 놓인 크기에서 300dpi 미만이면 "인쇄하면 흐릿할 수 있어요", 150dpi 미만이면 강한 경고.
- 색: RGB로 받고 PDF에 그대로 넣는다(흑백 인쇄 여부는 인쇄 주문 쪽의 일). 흑백 미리보기 토글을 제공한다.

### 6.5 주석

- 넣기: .docx 각주·미주를 가져오고, 직접 쓰기에서는 "주석" 버튼으로 넣는다. 본문에는 위첨자 번호가 붙는다.
- 위치: 책 전체에 하나. **쪽 아래**(기본) / **장 끝** / **책 끝**. 번호는 장마다 1부터.
- 쪽 아래 주석은 참조가 있는 글줄과 같은 쪽에 놓는다. 그 쪽에 자리가 없으면 그 글줄부터 다음 쪽으로 넘긴다.
- 주석 하나가 본문 높이의 1/3을 넘으면 점검에서 "책 끝 주석으로 바꾸면 읽기 편해요"라고 권한다(MVP에서는 쪽 아래 주석을 두 쪽에 나누지 않는다).

### 6.6 책 디자인

| 프리셋 | 본문 서체 | 본문 크기 / 줄 간격 | 정렬 | 장 시작 | 어울리는 책 |
|---|---|---|---|---|---|
| 에세이 | 명조 | 10pt / 170% | 양쪽 맞춤, 첫 줄 들여쓰기 1자 | 같은 면 시작 | 에세이, 자서전, 여행기 |
| 소설 | 명조 | 10pt / 160% | 양쪽 맞춤, 첫 줄 들여쓰기 1자 | 한 면 전체 | 소설, 긴 이야기 |
| 실용 | 고딕 | 9.5pt / 165% | 양쪽 맞춤, 문단 사이 간격 | 같은 면 시작, 장 번호 크게 | 강의록, 안내서 |
| 여행 | 명조 | 10pt / 165% | 양쪽 맞춤, 문단 사이 간격 | 같은 면 시작, 장의 첫 사진이 가로면 크게 | 여행기, 가족 문집 (사진 많은 책) |

- 쉬운 조정 4가지: 글자 크기(작게 −0.5pt / 보통 / 크게 +1pt), 줄 간격(좁게 / 보통 / 넓게), 본문 서체(명조 / 고딕), 사진 크기(작게 / 보통 / 크게 — 사진 규격 9.1).
- 프리셋별 사진 기본값(반 폭 자리, 쪽당 장수, 설명 번호, 한 면 채움)은 사진 규격 6.6.
- 책 크기: 46판(128×188mm), 신국판(152×225mm, 기본), A5(148×210mm). 여백은 판형마다 프리셋이 정한다.
- 서체는 인쇄·PDF 포함 라이선스를 확인한 서비스 폰트 목록에서만 고른다.
- **이 책의 모양들(모양 사전):** 프리셋마다 시·편지·문자·상자·인용 같은 이름별 모양과 강조·한자 병기 방식을 정해 둔다. 작가가 이름 하나의 모양을 고치면 책 전체에 적용된다. 구조와 기본값은 `2026-10-12-book-markup-design.md` 6절.

### 6.7 인쇄 전 점검

점검 결과는 "고쳐야 해요"(내보내기 막음)와 "확인해 보세요"(내보내기 가능) 둘로 나눈다. 항목마다 "그 자리로 가기"를 둔다.

| 항목 | 등급 | 작가에게 보이는 말 |
|---|---|---|
| 내용 없는 장 | 고쳐야 해요 | "3장에 글이 없어요" |
| 표현할 수 없는 글자 | 고쳐야 해요 | "서체에 없는 글자가 있어요: ㉿" (kayak 두부 대체가 일어난 곳) |
| 사진 해상도 | 확인해 보세요 | "인쇄하면 흐릿할 수 있어요" (사진 점검 전체는 사진 규격 8절 G1~G8) |
| 외톨이 줄 | 확인해 보세요 | "문단의 마지막 한 줄만 다음 쪽으로 넘어갔어요" (조판기가 피하지 못한 곳만) |
| 긴 쪽 아래 주석 | 확인해 보세요 | 6.5 참고 |
| 총 쪽수 | 확인해 보세요 | "인쇄를 위해 끝에 빈 면 2쪽을 더해요 (총 212쪽)" |

### 6.8 내보내기

- **인쇄용 PDF:** 낱쪽, 판형 + 사방 3mm 재단 여백, 재단선 표시 선택, 글자는 아웃라인(kayak이 글리프를 SVG path로 그리므로 자연히 아웃라인).
- **확인용 PDF:** 펼침면, 재단 여백 없음. 가족·편집자에게 보여 주는 용도.
- PDF는 서버(Node)에서 만든다. 화면 미리보기와 같은 조판 결과(9절 쪽 목록)를 쓴다.

## 7. 오류와 예외

| 상황 | 처리 |
|---|---|
| .docx를 읽지 못함 | "이 파일은 열 수 없어요. 워드에서 다른 이름으로 저장(.docx)한 뒤 다시 올려 주세요" + 붙여넣기 안내 |
| 원고가 너무 김 (예: 2,000쪽 추정 이상) | 올리기 전에 알리고, 책을 나눌지 묻는다 |
| 폰트 로딩 실패 | 미리보기는 "서체를 불러오지 못했어요. 다시 시도" 버튼. 서버 PDF는 제한 시간 뒤 실패로 기록하고 작가에게 다시 만들기 안내. kayak은 지금 폰트 실패 때 Promise가 끝나지 않으므로(`docs/usage/03-textbox-api.md`) 조판기가 제한 시간을 건다 |
| 조판 중 원고 수정 | 조판은 장 단위로 다시 한다(8.3). 진행 중 결과는 버리고 마지막 원고로 다시 |
| 되돌리기 | 원고 편집은 편집기 undo, 차례·디자인 변경은 책 단위 "이전 버전" 목록(자동 저장 시점) |

## 10. 시스템 구조

```
원고 입력 ──▶ 원고 변환기 ──▶ Book JSON ──▶ 조판기 ──▶ 쪽 목록 ──▶ 렌더러 ──▶ 화면 미리보기 (브라우저)
(붙여넣기,     (docx/HTML/      (구조 +       (쪽 나누기,   (쪽마다                    └▶ PDF (Node)
 docx, 편집기)  텍스트 → 블록)    디자인 설정)   kayak 측정)   놓인 조각)
```

### 10.1 Book JSON (엔진과 독립)

```jsonc
{
  "meta": { "title": "", "author": "", "published": "2026-11-01", "publisher": "", "isbn": "" },
  "design": { "preset": "essay", "trim": "shinguk", "fontSize": "normal", "lineSpacing": "normal",
              "bodyFont": "serif", "chapterStartRight": true, "folio": "outer-bottom",
              "runningHead": true, "notePlacement": "page" },
  "sections": [
    { "id": "s1", "zone": "front", "kind": "prologue", "title": "여는 글", "blocks": [ ... ] },
    { "id": "s2", "zone": "body", "kind": "chapter", "number": 1, "title": "바다로 가는 길",
      "blocks": [
        { "type": "paragraph", "runs": [ { "text": "그해 여름", "marks": ["strong"] }, { "text": "은 길었다." },
                                         { "noteRef": "n1" } ] },
        { "type": "heading", "level": 2, "runs": [ { "text": "첫날" } ] },
        { "type": "image", "asset": "a1", "size": "page", "caption": "남해 바다" },
        { "type": "box", "name": "시", "blocks": [ ... ] }
      ],
      "notes": { "n1": { "runs": [ { "text": "1998년 7월." } ] } } }
  ]
}
```

- 블록은 heading, paragraph, box(이름 붙은 상자 — 인용은 `name: "인용"`), image, gallery(사진 묶음), break(장면 바꿈), directive(새 쪽 등). 사진 파일은 책의 `assets`(사진함)에 두고 블록은 id로 가리킨다 — 사진 규격 5.4. 글자에는 marks(strong, emph)와 이름 붙은 꾸밈(span: 한자, 방점 …). 전체 대응은 `2026-10-12-book-markup-design.md` 8절.
- 디자인은 이름 붙은 값(`"normal"` 등)으로만 저장하고, 실제 pt·mm는 프리셋 표가 정한다. 프리셋을 고쳐도 기존 책이 따라간다.

### 10.2 조판기 (새로 만든다)

입력: Book JSON. 출력: 쪽 목록 — 쪽마다 번호, 좌우, 종류(빈 면, 장 시작 면 등), 놓인 조각(문단의 글줄 범위, 사진, 쪽 아래 주석 영역, 머리글, 쪽 번호).

1. 부분마다 시작 면 규칙(5절, 6.2)을 적용하고, 필요하면 빈 면을 넣는다.
2. 블록을 순서대로 남은 높이에 놓는다. 문단은 kayak으로 글줄을 측정해 글줄 단위로 나눈다.
   - 문단 첫 줄 하나만 쪽 끝에 남거나, 마지막 줄 하나만 다음 쪽으로 넘어가지 않게 한다(최소 2줄).
   - 제목은 뒤 문단의 첫 2줄과 같은 쪽에 둔다.
3. 쪽 아래 주석이 있으면 참조 글줄을 놓을 때 주석 높이를 쪽 아래에서 뺀다. 들어가지 않으면 그 글줄부터 다음 쪽으로.
4. 사진은 사진 규격 6절(자동 크기·자리, 줄이기·미루기, 묶음, 한 면·펼침면). 놓은 결과와 함께 "자동이 고른 값과 이유"를 쪽 목록에 남긴다.
5. 모든 부분이 끝나면 차례·쪽 번호·머리글을 채운다.

**장 단위 독립.** 장은 늘 새 쪽에서 시작하므로 장의 조판 결과는 다른 장과 무관하다. 원고를 고치면 그 장만 다시 조판하고, 이후 장은 쪽 번호와 빈 면만 다시 매긴다. 미리보기 반응 속도의 핵심이다.

### 10.3 렌더러

- 쪽 하나 = SVG 하나. 문단 조각은 kayak이 그린 문단 SVG에서 해당 글줄 범위만 잘라 놓는다(10.4 K2).
- 브라우저 미리보기와 Node PDF가 같은 쪽 목록과 같은 kayak 렌더를 쓴다. PDF는 쪽 SVG를 PDF로 옮긴다(도구는 계획 단계에서 정함. 새 의존성은 승인 후 추가).

### 10.4 kayak에 필요한 것

| # | 필요 | 지금 kayak | 방법 |
|---|---|---|---|
| K1 | 문단을 주어진 너비에서 글줄로 나눈 결과: 글줄마다 글자 범위, 높이, 기준선 | 텍스트 상자 전체 높이(`get_dimension`)만 공개. 글줄 정보는 내부(`TextBoxDom`의 `DomLine`) | 공개 API 재설계(로드맵 #1)에 "측정" API로 넣는다 |
| K2 | 글줄 범위만 렌더 | 상자 전체를 SVG로(`snapshotAsSVG`) | 처음에는 K1의 글줄 위치로 문단 SVG를 잘라 쓴다(엔진 변경 없음). 이후 영역/흐름(#2)에서 정식 지원 |
| K3 | 주석 참조 위치 → 글줄 | 이름 붙은 범위(`ATTR_NamedRange`)와 위치 찾기(`TB_LocationFinder`)가 있음 | 주석 참조를 이름 붙은 범위로 표시하고 K1 결과에서 글줄을 찾는다 |
| K4 | 주석 번호 위첨자 | 기준선 이동 속성 없음 | 새 글자 속성 필요(엔진 기능 추가 — 별도 설계) |
| K5 | 굵게·강조 | `bold`는 SVG 렌더에 효과 없음(`docs/usage/04-editing-and-style.md`). 기울임 속성 없음 | 굵게는 서체의 Bold 스타일로(`set_font_family`). 강조(`*글*`)의 모양은 모양 사전이 정한다(방점 / 다른 서체 / 굵게 / 밑줄) |
| K6 | 한글 금칙(닫는 괄호·마침표가 줄 첫머리에 오지 않게) | 줄바꿈은 공백 기준 어절 단위. 금칙 처리 코드는 찾지 못함 | 문장부호는 어절에 붙어 대부분 문제없음. 공백 뒤 문장부호·여는 괄호의 경우를 확인하고 필요하면 엔진에 추가 |
| K7 | Node에서 폰트 실패가 오류로 드러남 | Promise가 끝나지 않음, Node에서 `alert()` 부르는 경로(`docs/issues.md` #7, #8, #10) | PDF 서버 전에 고친다(로드맵 #4 결함 수정과 함께) |
| K8 | 방점(글자 위 점) | 없음 | K4와 같은 글자 장식 계열로 설계. 강조의 기본 모양이 방점이면 첫 출시에 필요 |
| K9 | 루비(한자 위에 작게) | 없음 | 첫 출시는 괄호 병기만 하므로 나중 |
| K10 | 글 옆 사진: 글줄마다 너비가 다른 문단 | 상자 하나의 고정 너비 | 처음에는 K1로 좁은 폭 N줄 + 남은 글자 범위를 본문 폭으로 다시 조판해 잇는다(엔진 변경 없음). 정식 지원은 영역/흐름(#2). 사진 규격 11.2 |

모양 사전(이름 → 모양)은 서비스 층에서 구체 속성으로 풀어 kayak에 넘긴다. kayak에 이름 붙은 문단 스타일을 두지 않는다.

## 11. 검증

- **조판기:** 고정 원고 픽스처(장 3개, 주석, 사진, 긴 문단)로 쪽 목록을 스냅샷 테스트. 홀수 시작·빈 면·외톨이 줄·주석 자리 규칙마다 특성 테스트.
- **장 인식:** 패턴별 표 기반 테스트, 실제 작가 원고 샘플 10개 이상으로 정확도 측정.
- **미리보기 = PDF:** 같은 원고로 브라우저 쪽 SVG와 Node 쪽 SVG를 비교.
- **사용성:** 첫 책 작가 5명에게 목업으로 ①~⑤를 해 보게 하고, 막힌 말과 화면을 기록한다.
